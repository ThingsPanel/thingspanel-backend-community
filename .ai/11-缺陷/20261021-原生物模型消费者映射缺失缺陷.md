## 范围和状态

用户报告设备详情、可视化选数、自动化中的映射缺失。本次只读核查代码与 23.254.236.109 测试部署，未发布模型、未修改设备绑定、未修改业务代码或重启服务。使用独立 QA 租户登录读取接口，未使用正在供用户登录的管理员会话。

后端版本 main-1.3.0-99c17f62；前端来源为 1156db2d。这里确定的主要问题是字段标识符到显示名称、单位及模型字段目录的映射；枚举值到标签的覆盖缺口另列，不能混为同一现象。

## 根因一：草稿与固定发布版本不同

设备详情 Web 遥测页已有原生名称、单位、枚举装饰逻辑（前端 src/views/device/details/modules/telemetry/telemetry.vue:378）。ThingsVis 新宿主也读取绑定的原生快照（src/components/thingsvis/ThingsVisAppFrame.vue:983）。二者经过 native-model-consumption.ts 的版本与快照校验。

当前 _data1 的定义只在草稿，所以这两个已接入的入口看不到名称/单位符合固定快照约束。需要用户主动发布新版本，再显式升级设备模板/配置绑定。_data2 在当前草稿也没有定义，不能自动推断它的名称。

## 根因二：消费接口仍停留在 Legacy

- 可视化旧选数器 DeviceMetricsSelector.vue 和 panel/ui/card-form.vue 通过 service/api/panel.ts:31 调用 GET /device/metrics/:id。
- 后端 internal/service/device.go:1203 GetMetrics 只以 DeviceTemplateID 查旧表，未读取 NativeThingModelID/SnapshotID/Revision；原生绑定时只有实际数据标识符，没有名称、单位和未上报模型字段。
- 自动化 edit-premise.vue、edit-action.vue 仍通过 service/api/automation.ts 调用 device 与 device_config 的 metrics 菜单。
- internal/service/device_config.go:408、529 在 DeviceTemplateID=nil 时直接返回 nil。原生绑定要求旧模板 ID 为 NULL，因此按设备模板选择的条件/动作目录为空。
- internal/service/device.go:1430、1659 的设备动作/条件菜单也只从实际值及旧模板补充元数据。

实测 HTTP 200、业务码 200：

| 接口 | 当前结果 |
|---|---|
| /api/v1/device/metrics/{deviceID} | _data1、_data2，label=NULL，无模型目录 |
| /api/v1/device/metrics/condition/menu?device_id=... | 仅原始字段，名称/单位为空 |
| /api/v1/device/metrics/menu?device_id=... | 仅原始字段与旧自定义分组，无原生命令 |
| /api/v1/device_config/metrics/condition/menu?device_config_id=... | 无 data |
| /api/v1/device_config/metrics/menu?device_config_id=... | 无 data |

即使发布并绑定新版本，这些 Legacy 消费接口的缺口仍然存在，不能把版本更新当成完整修复。

## 额外静态缺口：枚举展示未全覆盖

前端 native-model-resources.ts:64 能把原生 ENUM 转换为 PlatformField.options。Web 遥测与属性/事件页有部分消费。App telemetryDataCards.vue:28 只补名称/单位、模板仍渲染原始 i.value；manage/device-readings-compact.vue 也只补名称、单位和基础类型，未传递原生 options 到旧 enum 展示。当前绑定快照没有 ENUM，故本轮未声称已复现特定枚举值的实际页面失败。

## 修复方向（未实施）

1. 保留固定快照规则，增加草稿变更与绑定旧版本的明确提示，不自动读取最新草稿。
2. 给可视化选数、自动化设备/配置条件与动作目录接入同一个带身份/租户校验的原生绑定快照读取边界，输出名称、单位、类型、枚举与参数；写操作只允许 COMMAND。
3. 统一 Web、App、紧凑数据展示中的原生元数据转换，原始上报值保持不变，仅在展示层应用标签。
4. 验证发布前/发布后未升级/显式升级三种状态，旧发布快照不漂移；同时覆盖未上报字段、无绑定、快照失败、租户隔离、枚举值类型和自动化真实执行身份。

此前部署冒烟仅覆盖创建、发布和绑定，不构成这三个消费者入口的验收。当前处于根因已确认、修复未执行状态。
