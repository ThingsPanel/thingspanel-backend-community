# 市场原生模板闭环修复交付（20261022）

## 结果

社区发布、Horizon 展示和下载统一识别原生物模型 v1 包。商品封面与模型资源封面分开，市场版本内容冻结；旧模板可浏览，安装前明确提示转换要求。核心规则见 [市场原生模板](../00-项目核心/市场原生模板.md)。

## 修改范围

| 仓库 | 变化 |
| --- | --- |
| Community backend | 发布包独立携带模型封面来源；下载解析市场相对资源地址、校验业务状态及封面 SHA256；提供显式旧模板草稿转换工具 |
| Community frontend | 详情可选具体版本，展示原生/旧版/不可用状态；设备配置下载与新增设备入口先检查所选版本兼容性 |
| Horizon | 原生依赖校验、四类字段/枚举/参数摘要、完整包校验和；内容寻址保存包和封面；并发串行保护发布，版本/待审批提交原子写入；旧客户端不能误装原生包，原生客户端不能误装旧包 |
| Horizon Portal | 展示原生能力和版本兼容信息，读取失败明确提示；新上传必须提供版本及完整原生包 |
| 工作区与四仓库 AGENTS.md | 增加最小有效验证规则，避免无关、重复及只复述实现的测试 |

Encore 模型 API 和已有设备绑定未修改。沿用现有安装映射、幂等、原生快照读回及固定版本绑定。

## 本地旧包转换

在 Community backend 根目录使用 PowerShell：

```powershell
go run ./cmd/market-template-convert -input '..\.tmp\legacy-template.json' -output '..\.tmp\native-draft-report.json'
```

输入为旧市场下载 JSON（可带 `code=0,data` 外层）。输出包括 model/resources 草稿、封面资产来源及下一步说明。命令只读输入并创建新报告文件，不覆盖已有报告，不调用远程服务。缺失或含歧义字段时明确报错。

发布者审核草稿、复制资源并通过原生 API 创建/发布模型，绑定本地配置后使用新市场版本发布；不能直接把草稿当作已发布市场包。本次未批量转换已有市场数据。

## 部署与限制

1. 先升级 Horizon market-service 并应用 `013_freeze_template_versions.sql`，再发布 Horizon Portal、Community 后端和社区前端。新社区前端需要 Horizon 的版本兼容字段。
2. 新版 Community 会发送 `native_cover_url`；旧 Horizon 不识别此字段，不能在未升级市场服务时依赖封面分离。发布前应按此顺序联动上线。
3. 新版本必须具有完整原生依赖。历史版本没有内容校验和时拒绝覆盖，需换新版本号发布。
4. 保留现有模板级审批机制；此处不引入独立版本审批系统。新版本提交仍按既有模板级待审批状态处理。
5. 历史原生包缺少冻结封面字段时保留原行为，无法恢复已被改动的历史图片；发布者应重新发布新版本。
6. 当前 v1 支持原生封面资产和内嵌图表配置；图表外链图片等未在资产清单中的引用仍明确拒绝，不静默丢弃或依赖发布者内网地址。
7. 实验使用专用本地数据库 schema 和独立测试容器，清理后不保留服务；未操作线上服务器、数据库或用户绑定。
8. 尚未在完整运行的 Encore、Community、Horizon 和浏览器环境中做跨租户端到端验收。既有单元测试验证了原生导入/源快照复用边界，本地服务往返不能替代正式上线验收。

实施状态：根因分析、方案确认、代码修复和必要本地验证完成；远程部署、存量迁移与完整线上验收未执行。
