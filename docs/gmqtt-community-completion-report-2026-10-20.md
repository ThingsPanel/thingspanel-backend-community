## 一、给技术总监的汇报

### 修改思路与依据

核心问题是 Broker 直接承担业务身份/转换，以及内存受理和早确认留下的恢复窗口。采用上游 Mosquitto 2.1.2 独立协议进程，在既有社区 owner 后增加版本契约、可信封装和 SQL 事务边界。原生生命周期、租户/路由隔离和事务整合由主代理负责；薄封装、测试、镜像证据和文档主要交由 Luna 实现并复跑。

### 模块前后、例子与验证

| 模块 | 修改前的风险/约束 | 当前变化与实测边界 |
|---|---|---|
| Broker 与身份 | 业务逻辑耦合旧 GMQTT；权限和生命周期需逐层核查 | 固定上游 2.1.2、C ABI/Go driver、Owner HTTPS/有限 ACL、控制租约；Linux 镜像与 SBOM 已生成，部分原生链通过 |
| 可靠入账 | 内存队列和确认窗口不能证明业务已持久接受 | EVT/ATTR 收据、领域变更与 effect intent 同事务；最终 TEL 批次有可信收据与 route fence。普通遥测早期 MQTT ACK 仍不能代表最终批次落库 |
| 崩溃重投 | 提交后 ACK 前崩溃可能再次处理 | 持久订阅在 CONNECT 前注册路由；无设备 source ID 的真实 SIGKILL 重投保持同 ingestion_id/UUID，数据库业务与意图各一条。未证明意图已执行或物理效果 |
| 多 cell | 全局领取 receipt 可能由错误连接处理 | worker 按配置 cell 领取，空 cell/不支持 scoped store 失败关闭；真实 PG 隔离、迁移及并发子项通过 |
| 状态和迁移 | 陈旧状态或跨主机时间比较可能误判 | 新鲜连接/活动与 unknown；SQL012 CAS、自动 runtime fence ACK、代次递增和 reviewed-plan CLI。receipt 因果改由绑定锁和新代次证明，连接仍要求真实且新鲜；单binding native A/1→B/2→A/3已独立复跑两次，目标ready hash仅fixture声明 |
| 命令 | 协议 PUBACK 容易被误解为执行成功 | 既有 command owner 保存意图、幂等、过期和 unknown；SQL013 preview/hash 授权/submit；真实 MQTT 到 Paho 测试设备 ACK 已通过，Encore 为契约 stub，人工UI未完成 |
| 语义/证据 | 裸数值缺少发布模型、单位和来源 | tenant-scoped 已发布 Encore 语义、只读状态、SQL014 遥测证据；独立设备采样时间未知，空单位明确未知。未验证 live Encore |
| AI 工具委托 | 既有运行时没有本项目受限工具与可信用户委托接线 | 默认关闭；120秒/20次/明确设备范围；每次重验父会话、用户和显式权限。Go固定TLS客户端保留服务端身份，Python现有runtime adapter核对tenant/user/thread/device；真实隔离RPC串联通过，未部署线上登录/线程交接 |
| 迁移操作审计 | freeze外的批准文件hash/actor原先只输出到终端 | CLI prepare/activate/rebase在状态变更同一事务追加operator_apply；注入审计写失败会回滚状态和阶段事件。actor/hash为DB调用者标签，重试可追加；非签名人类审批，完整运维认证待验 |
| 离线独立对账 | 只看总数可能掩盖一丢一重及串租户 | 七阶段有界/hash输入按事件、tenant/device、receipt/effect和deadline判定；正确1k包与四类各100注入自检通过。尚未连接正式采集，不是零丢失或时延认证 |

### 收益、退化与下一步

收益是权限/入账/命令结果有明确责任和可复核记录。新增 SQL、控制依赖与持久数据也带来开销，目前无吞吐或成本优势结论。新 profile 对 custom command mapping、传统 raw/service/protocol 下发、OTA/expected-data 等仍有拒绝或兼容缺口；QoS2、wire-retained、延迟/恢复 Will 尚未完整认证。不能让这些在用设备直接迁移。

本轮推荐先确认社区现有在用下行入口，再仅补这些入口到新链的必要接线，并验证一个正常请求及必要拒绝场景。不能直接移除拒绝保护并改回任意raw发布，否则会绕过既有身份、路由和命令边界。是否接AI产品对话、是否存在社区OTA使用场景由用户判断；在判断前不继续这些草稿。72小时、配对性能、极限/批量故障测试不再是本轮开发前置条件。

## 二、给产品经理的汇报

### 修改思路与可感知变化

目标是让设备诊断与操作可以回答“依据是什么、是否有权限、目前做到哪一步”。设备身份与模型继续由既有 owner 管理；模型或界面只能提出确定性计划，人的授权绑定精确 hash，设备报告和后续观测分别记录。

例如，一个网关下设备状态过旧时，当前证据接口返回 unknown，而不展示精确离线；缺少采样时间或单位会显式标记。命令 preview 不发设备，授权后 submit 才进入现有耐久命令链；同键重试返回原命令，换键不能重复消费同一次计划授权。

### 社区实际功能与本次缺口

| 用户提到的项目 | 大白话解释 | 社区源码核查与当前判断 |
|---|---|---|
| OTA | 给设备远程升级固件 | 有后端路由/API封装，但未确认社区实际可用页面或在用场景；不能据此说社区已提供完整OTA产品。本轮不自行新增OTA产品 |
| 预期数据 | 页面称“期望消息”：设备暂时不便接收时，保存待下发的消息 | 社区设备详情已有tab和列表/创建/删除API，支持telemetry/attribute/command；新profile拒绝部分路径是迁移兼容问题。线上版本是否展示、实际使用范围尚未核实 |
| 旧协议插件/自定义下行 | 将平台标准命令转成设备厂商要求的topic、payload或插件调用 | 与企业版无必然关系。入站版本化custom mapping已有有限支持；当前缺的是新耐久下行对service/protocol/custom command mapping的兼容，不能笼统说全部插件/自定义映射都被禁用 |
| AI正式对话 | 用户在产品里提问，AI按登录身份查询设备或提出操作计划 | 已有受限工具后端和隔离RPC证据，真实聊天入口尚未完成；不是基本Broker替换必需的协议功能 |
| 前端接线 | 让页面按钮、聊天和确认动作实际调用后端API | 源码组件存在不等于用户已能使用；新聊天BFF未实现，前端草稿未联调/部署 |

已验证的计划流程来自隔离PG/Redis、Encore HTTP契约stub、实际Mosquitto和Paho测试设备；未验证live Encore、真实登录聊天界面或物理动作。正式盲测、人效研究由用户后续自行安排；不再阻塞本轮开发。测试设备回执仍须与现场物理效果区分。

### 价值与推荐路径

当前价值是把设备证据和受控命令的后端责任理清，并暴露迁移遗漏。建议先保住社区正在使用的功能，补确认属于本期的兼容入口；AI真实聊天单独由用户决定是否纳入。新增功能冻结期间，只整理报告和已有证据，不把未完成UI或Host计作交付。尚无AI正确率、节省时间或客户可用性收益结论。

## 三、给公司老板的汇报
