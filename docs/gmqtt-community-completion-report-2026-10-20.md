## 一、给技术总监的汇报

### 修改思路与依据

核心问题是 Broker 直接承担业务身份/转换，以及内存受理和早确认留下的恢复窗口。采用上游 Mosquitto 2.1.2 独立协议进程，在既有社区 owner 后增加版本契约、可信封装和 SQL 事务边界。原生生命周期、租户/路由隔离和事务整合由主代理负责；薄封装、测试、镜像证据和文档主要交由 Luna 实现并复跑。

### 模块前后、例子与验证

| 模块 | 修改前的风险/约束 | 当前变化与实测边界 |
|---|---|---|
| Broker 与身份 | 业务逻辑耦合旧 GMQTT；权限和生命周期需逐层核查 | 固定上游 2.1.2、C ABI/Go driver、Owner HTTPS/有限 ACL、控制租约；Linux 镜像与 SBOM 已生成，部分原生链通过 |
| 可靠入账 | 内存队列和确认窗口不能证明业务已持久接受 | EVT/ATTR 收据、领域变更与 effect intent 同事务；最终 TEL 批次有可信收据与 route fence。普通遥测早期 MQTT ACK 仍不能代表最终批次落库 |
| 崩溃重投 | 提交后 ACK 前崩溃可能再次处理 | 持久订阅在 CONNECT 前注册路由；无设备 source ID 的真实 SIGKILL 重投保持同 ingestion_id/UUID，数据库业务与意图各一条。未证明意图已执行或物理效果 |
| 多 cell | 全局领取 receipt 可能由错误连接处理 | worker 按配置 cell 领取，空 cell/不支持 scoped store 失败关闭；真实 PG 隔离、迁移及并发子项通过 |
| 状态和迁移 | 陈旧状态或跨主机时间比较可能误判 | 新鲜连接/活动与 unknown；SQL012 CAS、自动 runtime fence ACK、代次递增和 reviewed-plan CLI。receipt 因果改由绑定锁和新代次证明，连接仍要求真实且新鲜 |
| 命令 | 协议 PUBACK 容易被误解为执行成功 | 既有 command owner 保存意图、幂等、过期和 unknown；SQL013 preview/hash 授权/submit；真实 MQTT 到 Paho 测试设备 ACK 已通过，Encore 为契约 stub |
| 语义/证据 | 裸数值缺少发布模型、单位和来源 | tenant-scoped 已发布 Encore 语义、只读状态、SQL014 遥测证据；独立设备采样时间未知，空单位明确未知。未验证 live Encore |

验证结果：一次 18 包 race 回归中 17 包通过，CLI 测试受 `umask 077` 影响而失败；修正测试创建文件的权限前提后，同环境单独重跑 CLI 包通过，生产逻辑未为此放宽。`go build -p 1 ./...` 通过。三项预期 skip 为子进程 helper、未在该轮启用固定 Linux 镜像的 SIGKILL、未启用的旧 GMQTT 健康测试。固定 Linux 镜像的 SIGKILL 无 source ID 用例另行连续运行两次；固定名原始日志仅保留最后一次。完整失败、诊断和复跑见[验证记录](gmqtt-evidence-2026-10-19/final18-race/README.md)。

另有新链 C100/R100 每秒、60 秒 6,000 条健康对账与旧链 5 秒 500 条健康对账；它们没有构成同条件收益测试。旧版本 ASan 压力不能替代当前源码认证。此前 Activate 单次失败在诊断 10 次中未复现，其具体触发原因仍未确认；确定性时钟偏移回归证明本轮因果修正的必要边界。

### 收益、退化与下一步

收益是权限/入账/命令结果有明确责任和可复核记录。新增 SQL、控制依赖与持久数据也带来开销，目前无吞吐或成本优势结论。新 profile 对 custom command mapping、传统 raw/service/protocol 下发、OTA/expected-data 等仍有拒绝或兼容缺口；QoS2、wire-retained、延迟/恢复 Will 尚未完整认证。不能让这些在用设备直接迁移。

推荐下一步先冻结真实在用协议与容量，补兼容和当前版本故障矩阵，再在足够磁盘的隔离环境做三次配对收益与完整 72 小时稳定性。随后执行两 cell 灰度/回退及接管演练。当前机器曾接近磁盘满，只回收了本任务复制的约 1.4GiB Go 缓存，仍不适合作为未经容量规划的长稳场地。

## 二、给产品经理的汇报

### 修改思路与可感知变化

目标是让设备诊断与操作可以回答“依据是什么、是否有权限、目前做到哪一步”。设备身份与模型继续由既有 owner 管理；模型或界面只能提出确定性计划，人的授权绑定精确 hash，设备报告和后续观测分别记录。

例如，一个网关下设备状态过旧时，当前证据接口返回 unknown，而不展示精确离线；缺少采样时间或单位会显式标记。命令 preview 不发设备，授权后 submit 才进入现有耐久命令链；同键重试返回原命令，换键不能重复消费同一次计划授权。

### 已验证与仍不可宣传的内容

- 已验证：隔离 PG/Redis、Encore HTTP 契约 stub、真实 Mosquitto、Paho 测试设备的预览到 ACK；只读查询的租户/子设备/窗口隔离，以及状态变化、模型变化、权限撤销等部分拒绝路径。
- 尚未验证：真实用户界面与 AI 工具安装、live Encore、完整首个诊断场景、留出集 50 例三轮盲测、两名真人操作员 20 题人效研究、物理设备效果。测试设备的成功回执不能显示成现场故障已修复。
- 兼容性：默认保留旧 profile，新能力显式开关；新 profile 拒绝的在用家族必须先补齐或由 G0 冻结迁移边界，不能在产品中隐藏。

### 价值与推荐路径

当前价值是为诊断和受控操作准备可信底座，尚无 AI 正确率、节省时间或客户可用性收益。建议 Broker 验收与 AI 产品流并行推进；AI 复用既有运行 owner，先补受限用户委托与固定工具 adapter，再做预算受控的真实场景。当前还不能把工具 API 存在视为 AI 场景完成。

## 三、给公司老板的汇报

### 投资完成到了哪里

已形成可构建的社区候选、固定 Linux Broker 镜像、SBOM、部署/迁移工具和多项真实协议/数据库证据。Luna 承担了大部分明确模块与测试，主代理负责高风险设计、复核和整合。企业版没有混入本期投入。

### 已有收益与尚未兑现的承诺

已有的是后续可维护与可审计的工程资产；尚未证明的是“同 SLO 吞吐提升 50% 或单位全成本下降 30%”、完整 72 小时稳定性、灰度成功和 AI 人效提升。当前没有可依据的项目回报率或人效百分比。业务 LLM 实验尚未进行，编码代理费用也没有完整审计，不能报总成本为零。

### 决策与下一步对比

| 路径 | 可获得的结果 | 当前建议 |
|---|---|---|
| 继续社区 1A 质量与运维验收，同时建设 1B 的受限 AI 工具接入 | 保留完整一期目标，并逐项取得生产和价值证据 | 推荐；先落实真实样本、隔离长稳资源和验收参与人 |
| 在完成 Broker 认证后先关闭 AI 发布基础能力 | 可按 G3/G4 单独决定基础发布，完整项目仍须 G5 | 作为阶段交付选项，须保持 AI 未完工的合同口径 |

尚需实际条件：足够容量的隔离长稳/配对环境、真实在用协议样本、两 cell 操作演练、live Encore 接线，以及计划要求的独立真人评审/操作员。三份代理报告不替代这些人和运行时长。
