# HA 插件与可执行连接器资源中心：目标分析（2026-11-06）

## 1. 结论

HA 插件一键安装的完整目标是：**用户在资源中心发现官方审核的连接器 → 官方发布流程构建并签名目录 → 安装器仅从官方受信目录同步 → 本机 Agent 再验签并按不可变镜像摘要安装 → 后端按租户和代次签发运行身份并编排 → 用户在平台配置 HA 接入点与实体 → 上行、下行和回执通过真实栈验证。**

目前 Horizon 资源中心已有模板、看板、解决方案 Bundle 和插件依赖表达，但**没有可执行连接器市场**；本机 Agent 消费安装器提供的签名目录，不会从 Horizon 直接执行插件。因此目标必须补上资源发现、官方审核发布、在线同步和本机验签的完整链，不能把资源中心排除在外，也不能把任意市场镜像直接执行。

首期固定安全边界是“**官方审核签名 + 受信目录 + Agent 本机二次验签 + 不可变镜像摘要**”；目录如何交付仍待决：可做安装器在线同步，也可先由受控发布流程分发签名目录文件，待在线服务准备好再接入。Horizon 负责发现、详情、兼容性与审核状态；未审核内容只能展示为候选，不能安装。两种交付方式都不得放宽 Agent 的本机验签或允许任意镜像执行。

## 2. 范围与边界

本方案覆盖 HA 南向连接器和之后的同类服务插件。模板/看板/Bundle 仍是现有资源类型；插件依赖字段只是 Bundle 元数据，不能据此当作有连接器安装市场。此次目标包含发现、发布、签名目录、在线同步和最终安装使用路径。

插件容器继续由主机 Agent 安装、启停和回收；后端控制面管理租户、安装状态、服务登记和受管身份；Broker、遥测和设备操作仍走现有数据面。插件 HTTP 调用必须使用绑定租户、服务和代次的受管身份，匿名入口保持封闭。资源中心不是远程执行入口，后端也不能从市场任意下载镜像或重启主机服务。

## 4. 目标链路

```text
作者提交连接器源码与声明
        ↓ 官方 CI 构建多架构镜像，固定 OCI digest，执行安全/兼容性检查
资源中心审核并展示连接器详情与平台要求
        ↓ 批准后的受控发布流程生成规范化目录并签名
官方目录服务 / 受控分发端点（目录、签名、版本、有效期；制品在可信 Registry）
        ↓ 安装器在线同步（待决）或受控分发签名文件，Agent验签
本机受信目录缓存（保留来源、目录版本、签名和 digest）
        ↓ 后端读 Agent Catalog；Agent 再验签、校验条目、架构、digest 与权限
安装流程：身份/代次 → Agent Prepare → 一次性 grant → Activate → 进程健康
        ↓ 用户在平台配置 HA 服务接入点（URL + token）并选择实体建设设备
受管身份拉取接入点；设备凭据按范围下发；遥测上行、控制下行、回执读回
```

**信任原则：**目录签名确认“官方批准了这个条目”；OCI digest 确认实际镜像字节与批准制品一致；Agent 本机验签确认主机执行端遵守授权。TLS 保护传输，不能代替目录签名；市场登录态不能代替主机端验签。目录签名与镜像摘要需统一规范化契约，明确覆盖字节、字段、编码和签名排除规则，并以跨语言 fixture 校验。

## 5. 首期资源中心与目录方案

### 方案候选：官方签名目录（交付方式待决）

1. **发现与详情。**Horizon 增加连接器类型、官方维护者、支持的 ThingsPanel/HA 版本、CPU 架构、权限/数据范围、配置方式、版本记录、审核状态和安全公告。只有已审核且发布的版本显示“可安装”。
2. **审核发布。**官方 CI 从审核 tag 构建 amd64/arm64 镜像并取得各自 immutable digest；生成与镜像、入口、健康检查、服务标识、网络、能力权限和最低 Agent 版本绑定的目录条目。审核批准后由隔离 signer 签署精确字节；私钥不进入 Horizon Web、Agent、安装器仓库或构建日志。首期人工批准，不把市场作者签名当成官方执行授权。
3. **目录交付待决。**在线方案由安装器只访问预设官方目录 URL，把目录与签名原子写入本机受限缓存；同步失败保留最后一个有效目录并报告过期/联网失败。首期可替代为受控发布流程分发同格式签名文件并校验来源/版本。两种方式最终都由 Agent 从本地路径加载并用本机信任根再次验签；Agent 不接收任意市场 URL，不跟随到非批准镜像源的重定向。
4. **安装执行。**目录条目只允许受信 Registry 的不可变 digest 和固定 profile 字段。Agent 拒绝 mutable tag、未知架构、未声明挂载/特权能力、未知字段、过期目录、低于本机已接受目录版本的回滚及签名目录外的插件 ID。镜像 digest 不匹配即失败关闭。
5. **密钥治理。**首个正式目录前确定离线 root、在线发布签名密钥、客户端内置根公钥、根轮换/撤销、紧急下架、历史目录失效和恢复演练。根变更经已信任根签署的新根或发行版升级分发，不能由市场在线提供未经认证的新公钥。

签名目录保留资源中心发现体验，同时不让浏览器或市场服务直接执行主机命令。目录在线同步和受控文件分发是待决的交付选项，执行决定始终由本机 Agent 验证。首期不承诺作者自助发布、任意 URL/Registry 或容器自动升级；自动更新要另行定义租户审批、健康回滚和版本策略。

### 不采用的方案

- **任意市场镜像直装：禁止。**镜像 URL 可变，作者可替换镜像，Registry 凭据/重定向会扩大执行链权限；TLS 不能证明官方批准。
- **Horizon API 返回条目后由 Agent 直接拉起：不采用。**这会让市场服务/API 故障直接触达宿主执行权限，并绕过现有签名目录机制。
- **开放作者签名作为首期执行授权：不采用。**作者投稿和官方执行授权分离；多签名信任须先定义身份、撤销与争议处理。

## 6. HA 零字段安装与配置边界

- 安装 HA 插件时不要求 HA URL、长期令牌或实体 ID。Agent 从签名目录取得插件定义和镜像；不通过恢复通用 `env_user` 机制索取这些现场信息。
- 用户在平台“服务接入点”创建 HA 连接，填写 HA URL 和 token；表单用密码输入、脱敏回显，并支持轮换。之后用户从 HA 实体选择设备。安装状态和连接状态分开显示。
- **健康和接入状态分开：**容器 `/health` 只表示进程可响应；每个服务接入点分别报告“身份有效、接入点可读取、HA 地址可达、token 有效、实体同步完成、设备数据路径可用”。一个 HA 插件进程可能管理多个独立接入点，不能用单一进程健康覆盖各接入点状态。
- 服务接入点列表通过受管身份的 `plugin/service/access/list` 读取。P0 复核实际调用是否经 SDK 自动加 Bearer、token 对应当前代次，以及后端是否限定同租户和 service identifier；匿名、用户 JWT、伪造头继续拒绝。
- HA 长期 token 等凭据不进入安装请求、插件目录、错误信息、审计日志、镜像层、固定配置文件或 bearer/token 日志；HA URL 是接入点配置，不作为凭据泄漏验收项。voucher 密文存储和密钥管理需另行决策；已有请求/操作日志脱敏和 voucher 加密工作也须复验。

## 7. 续期、失败退避与重启恢复

Agent 执行租约和平台身份有效期是两个独立租约，必须由控制面同代次续期；Agent 失联时本机租约到期仍应停止容器。续租失败不能以“重新安装整个插件”作为日常保活方式。

建议维护动作为**同一 generation、同一身份密钥，只延长 identity expires_at 和 Agent execution lease，不重建容器、不重新签发身份、不重启插件**。续约周期应明显短于最短租约，可先按 5 分钟；身份和 Agent TTL 保持有上限。到期前 2 个周期告警。UI 分开显示 agent unreachable、identity expired、lease refused、health degraded 和 HA auth failed。

安装操作要持久化步骤、`operation_id`、幂等 `request_key`、尝试次数、下次重试时间、最近错误码和 Agent 回执。后端重启后先查询 Agent durable status 和平台登记状态，再续做缺失步骤；不得盲目从头签发新代次。Agent 离线/超时使用有上限的指数退避和随机抖动、并发/队列上限及可观测预算；超过预算进入 `waiting_operator` 或明确失败，不持续快速重启容器。

**身份令牌一次性回传的恢复决策待定。**身份存储目前只留哈希，签发 token 只回传一次；若后端在签发后、Agent 持久接收前崩溃，无法原样找回 token。需要在两种安全机制里先决策：A. 短保留期、本机密钥加密的 issuance outbox，Agent ACK 持久化后删密文；B. 按租户/实例/`operation_id` 绑定的安全幂等重放，重试取回同一结果且可撤销。不得把 token 明文写普通数据库、日志、安装行或交付文档。未定前不能把“后端重启自动续作”列为通过。

## 8. 用户路径与发布门槛

正式验收从资源中心发现开始：看连接器详情/权限 → 同步官方目录 → 检查兼容架构 → 零字段安装 → Agent 验签并按 digest 启动 → 进程健康 → 用户配置 HA 接入点 → HA 接入就绪 → 选实体建设备 → 当前值和历史可读 → 下发控制并读到真实 HA 状态/设备回执 → 重复安装保持单实例 → 后端重启、Agent 失联/恢复、同代续租无代次抖动 → 卸载后身份吊销、容器停止、旧身份被拒绝。

以下条件满足前只能称测试候选：

1. 四仓 commit、dirty 状态、镜像 tag/digest/架构、SDK 版本和 migration 已记录；从批准版本构建，不能把未提交源码混入不可追溯镜像。
2. 正式信任根、轮换/撤销流程和 Agent 端验签完成；正式 root 尚未建立是 P0 阻断项。
3. HA 镜像至少 amd64 与 arm64 构建通过，digest 和签名目录一致；旧 ARM64 digest 不自动代表最新制品。
4. PG migration 33–35 在最新 develop 的新装/升级路径自动执行且可重复；MySQL 未测不得默认自动运行，需负责人确定支持范围。
5. 官方目录签名校验通过；过期、回滚、未批准源被拒绝。市场静态页 200 不代表目录可用。
6. 受管身份真实请求、HA 数据/命令链、隔离租户、失败退避、进程重启恢复、租约失联停止均有证据。单元测试不等于用户路径通过。
