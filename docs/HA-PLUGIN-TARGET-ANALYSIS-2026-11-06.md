# HA 第三方服务插件：发布与安装目标（2026-11-06）

## 用户目标

只处理 HA 类型第三方服务插件（此处 HA 指 Home Assistant），聚焦正式发布和安装。目标路径：超管安装官方可信 HA 插件 → 租户用户在所属租户配置需认证的 HA 服务接入点 → 选择实体建设备并确认上报、下发。安装时 HA 凭据字段为零；凭据在接入点配置。HA 进程健康与各接入点认证/连接状态分开显示。

先核实现有插件接入、资源中心入口和授权流程，能复用就复用；不重做入口或另开设计。现有租户管理员安装 API/租户绑定不是“超管安装”已完成的证据，执行人须查清平台超管身份、系统级安装实例与租户接入点的关系，再提出最小必要契约并验证租户隔离；不得擅自选架构或扩大授权。

## 已知事实与证据边界

- 续期半成品：候选后端 `internal/plugininstall` 和 Agent renewal 实现仍在未提交工作区。已知失败路径证据为 Agent `/v1/grant` 对过期/旧代次返回 409；若后端把该拒绝视为“不可信”并升代重装，会触发容器反复重建。须对当前代码和日志逐分支核实，这是已知候选行为，不能泛化为当前正式版实测故障。真实稳定续租尚未证明。
- 历史真实链：`docs/tasks/T7b-DONE.md` §8 真实 HA 灯上报、开关下发通过；当时需手动迁移、刷新 Broker 范围、重启 owner/mosquitto/插件。`docs/tasks/PLUGIN-UI-DONE.md` 也记载 UI 安装后的上下行通过，但建设备走 API 模拟。T7 早期失败不代表后来从未打通；上述都不是当前固定发布版本的证明。
- 安装现状：候选 `internal/api/plugin_install.go` 测试明确要求租户管理员；身份签发按租户绑定。必须核实与超管发起、系统级插件安装、各租户独立服务接入点之间的关系，不能把既有 API 冒充目标能力。
- 资源中心网站现有插件/资源入口待在 Horizon 当前版本核实；先复用现有入口与发布流程。不得假定已存在“网站代平台安装”授权合同，也不得无依据新建跨站协议。
- 正式发布仍要求可验证的可信签名、可信公钥来源和与实际制品一致的不可变 digest；旧测试签名、旧摘要及 dirty worktree 均不构成发布证明。

## 范围和保护

保留：凭据不进日志；Agent 本机验签；最小运行权限；租户/服务授权隔离；续约不换代、不重启容器；断联有界退避与到期停止。HA 目录不声明 HA 凭据字段，其他插件通用 `env_user`/秘密能力保留。

首期只交付官方审核签名的 HA 制品和现有入口所需的最小接线。自动在线目录同步、第三方自助上架、通用市场、复杂密钥治理等延期。目录在线同步或受控分发按现状复用，不把任何一种未决方式写成已批准架构。

## 可独立验收闭环

1. **运行稳定：**修正续期拒绝分类和重启风暴，真实连续运行及短 TTL 证明同代续租；后端中断后按 Owner 立即接管，hostname 改变的重建最多等租约到期。
2. **正式发布：**冻结官方签名目录、可信公钥和匹配 digest 的 HA 制品；复核正式 compose 权限、Agent socket/token 接线、新装/升级和迁移。每项可独立验收。
3. **超管安装与租户接入：**先核实并复用现有插件安装 API、资源中心入口和权限机制，明确最小系统级安装与租户接入关系；超管安装，租户仅配置自身接入点和设备。隔离、身份绑定、健康状态、凭据保护单独验收。
4. **当前版本全链验收：**固定各仓版本，在真实 HA/Broker 完成安装、接入点认证、实体上报、命令与回执、续租/恢复、卸载吊销。历史已通路径只复验，不重复开发。

每阶段可单独验收。未提交工作区必须先盘点并保留；不 stash/reset/覆盖，不推送、不合并。具体小任务、入口与验收见[任务卡](HA-PLUGIN-TASKS-2026-11-06.md)。
