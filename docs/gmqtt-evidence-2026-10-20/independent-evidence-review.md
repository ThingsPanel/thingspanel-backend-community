# Independent evidence review — 2026-10-20

This is a read-only review of the current acceptance tracker, AC ledger, Linux image/SBOM evidence, native ingress and command reports, telemetry storage evidence, audit CLI evidence, planned-command report, and SIGKILL evidence. It is report material only: it is not a second human QA sign-off, a production acceptance, or a physical-device observation.

## Subcases supported by concrete evidence

- **Frozen image and packaging checks:** the Linux/arm64 Mosquitto 2.1.2 image is identified by image ID and build-context hash. Isolated QA checked UID/GID 1883, read-only root, required writable tmpfs, read-only secret/config mounts, Owner token allow/deny, audit CLI startup, and four nonempty bundled license files. Syft 1.54.1 generated SPDX and Syft JSON for this image. The scan is an inventory, not a vulnerability scan or legal conclusion. See [image runtime evidence](../gmqtt-evidence-2026-10-20-linux-image-runtime-smoke.md), [build record](../gmqtt-evidence-2026-10-20-build.json), and [SBOM provenance](sbom/provenance.json).
- **Strict native runtime path:** with the exact frozen Linux image, real Mosquitto/plugin, Owner HTTP over certificate-verified TLS, isolated PostgreSQL/Redis, and runtime fencing enabled, the native E2E reached all four fence acknowledgements and denied a post-fence PUBLISH without creating another receipt. The test config used `persistence false` and tmpfs, so this does not exercise broker disk recovery. See [image runtime evidence](../gmqtt-evidence-2026-10-20-linux-image-runtime-smoke.md).
- **Subscriber SIGKILL window:** in the no-`source_event_id` case, the subscriber was killed after durable receipt commit and before application MQTT ACK. The persistent replacement session received the duplicate with the same receipt UUID and `ingestion_id`; the database assertion verified SQL `source_event_id IS NULL`, then one processed receipt, one event row, and one automation effect. The `-race` test ran twice and did not skip. See [no-source result and logs](sigkill/nosource/).
- **EVT/ATTR/TEL software command paths:** the native application E2E evidence reports real MQTT ingress for each family, durable automation command creation, delivery to a Paho test device, and device-protocol ACK advancing the command to `device_reported_success`. This is a software protocol endpoint, not a physical actuator. See [native Owner/ledger E2E](../gmqtt-evidence-2026-10-19/native-mosquitto-owner-ledger-e2e.md) and [automation command E2E](../gmqtt-evidence-2026-10-19/automation-native-command-e2e.md).
- **Planned-command protocol path:** the native planned-command test records preview, human authorization, idempotent submit, delivery, and a scoped Paho device ACK. Its semantic endpoint is an `httptest` stub; it does not verify live Encore. The separate service-level and API tests also use isolated fixtures. See [planned-command report](../gmqtt-evidence-2026-10-19/planned-command-native-mosquitto-e2e-2026-10-20.md).
- **Targeted PostgreSQL invariants:** telemetry batch fencing/rollback, state freshness/projection, automation limiting, quarantine, command idempotency, and migration checks have specific isolated-PostgreSQL subcase evidence. These tests do not establish complete AC coverage or production schema deployment. See [telemetry batch fence](../gmqtt-evidence-2026-10-20-telemetry-batch-fence.md), [state boundary regression](../gmqtt-evidence-2026-10-19/broker-state-time-boundary-regression.md), [quarantine regression](../gmqtt-evidence-2026-10-19/broker-quarantine-regression.md), and the [AC ledger](../gmqtt-community-ac-ledger-2026-10-20.md).
- **Read-only audit CLI:** the CLI's isolated PostgreSQL tests cover pagination, tenant scoping, read-only enforcement, redaction, and incomplete-schema behavior. They do not prove production grants or migrations. See [audit CLI evidence](../gmqtt-evidence-2026-10-20-broker-audit.md).

None of these subcases is enough to mark an entire AC or gate PASS. The AC ledger currently has 22 PARTIAL, 40 PENDING, and 11 OUT_OF_SCOPE entries; it has no full AC marked PASS.

## Gates and claims that must remain open

- **G0-C:** the local runtime inventory is explicitly only a three-device developer-machine sample. It does not establish customer usage, retained contents, per-message QoS, expected-data usage, or production image/source equivalence. The old/new complete-stack paired baseline, frozen compatibility/sample matrix, and reproducible production workload ledger remain absent. Do not normalize empty `is_enabled` values as enabled based on this sample.
- **G1-C:** native ABI and selected protocol/runtime subcases are supported, but the current frozen image ran with broker persistence disabled. Full on-disk persistence/reboot recovery, delayed and restart-recovered Will, barrier-controlled peak auth overlap, and all in-use protocol compatibility cases remain unproved. The earlier ASan evidence is tied to an older source/image hash and cannot certify this frozen image.
- **G2-C:** receipt, business transaction, durable intent, command planning, runtime fence, and device-protocol ACK have subcase evidence. A receipt or intent proves a database outcome, not successful MQTT delivery; a broker PUBACK proves broker receipt, not platform acceptance; `device_reported_success` proves the test client's protocol ACK, not a physical action. The telemetry batch evidence also explicitly states that ordinary telemetry can be MQTT-ACKed before the final storage batch commit; that gap remains a live reliability boundary. Unsupported compatibility surfaces include enabled custom topic mappings and legacy service/protocol/raw downlink in `ingress_v1`; QoS2, wire-retained, and delayed/recovered Will are not fully certified.
- **G3-C:** no complete applicable-AC campaign, paired performance/capacity result, tested failure-and-reconciliation matrix, installation handoff, or 72-hour stability run is evidenced. There is no verified three-run same-condition benefit result. Generated load or shorter smoke runs cannot substitute for those criteria.
- **G4-C:** the isolated runtime fence proves a narrow protocol/control behavior. It does not prove a live route migration, production gray rollout, epoch transition and rollback with an operator, or production recovery. Keep the migration gate closed.
- **G5-C:** command-plan APIs and constrained command execution are not AI acceptance. AC-A01–A06 remain PENDING: no live Encore semantic verification, blinded three-run evaluation, held-out evidence set, cost result, or operator-effectiveness comparison is present. The Encore semantic/API tests cited here use `httptest` contract stubs or read-only source/API inspection.

No claim in this review should call a receipt, effect intent, command log, broker ACK, or test-device ACK “physical execution.”

## Evidence integrity and contradictions

- An earlier version of `gmqtt-evidence-2026-10-20-linux-image-runtime-smoke.md` had a stale SBOM-not-generated sentence and a broken SBOM link. The current version removes that sentence while retaining the older-ASan coverage limitation, and links to the checked-in SBOM directory.
- The two SIGKILL evidence locations represent two payload variants: one with a `source_event_id`, and one without it. The SIGKILL targets the adapter subscriber child process after receipt commit; the Mosquitto broker remains running and redelivers through the persistent service session. The no-source `-count=2` run wrote fixed filenames in one `nosource/` directory, so checked-in raw logs/result are from the last successful iteration, not two individually preserved run records. Do not claim per-iteration raw-log retention for that command.
- The native telemetry report correctly records that the early MQTT/bus ACK precedes the final durable batch commit. Acceptance dashboards must preserve this distinction and must not infer final storage acceptance from an MQTT-level ACK.
- The planned-command report records an earlier fixture panic and a passing rerun after installing a private SSE manager. This is transparent and appropriately scoped; retain the first attempt as a fixture failure, not as a product defect or passing run.

## Disposition

The evidence supports several useful engineering subcases on a pinned local image and isolated QA resources. The tracker’s overall PARTIAL/no-cutover decision is consistent with the reviewed evidence. Keep all G0–G5 open until their stated end-to-end criteria are satisfied by reproducible, scoped evidence and an actual operator/customer acceptance process.
