# 构建与发布版本

SYSTEM_VERSION 不再随发布手工修改。源码默认值为 dev，发布时由 Go 链接参数写入二进制。

| 场景 | 版本来源 |
| --- | --- |
| 本地 go run、IDE 调试、普通 go build | dev |
| main 自动部署 | dev-加本次完整 Git 提交 SHA |
| Release 包与 Docker 发布 | 本次发布的 Git Tag |

## 正式发布

1. 合并本次修改后，在需要发布的提交上创建版本 Tag，例如 v1.3.0。
2. 发布该 Tag 的 GitHub Release，现有两个工作流分别构建安装包和镜像。
3. 流水线检出 Tag 对应代码、注入版本并检查产物版本。正式发布无需修改 global.go。

手动运行工作流必须填写已有 Tag。支持 v1.3.0、v1.1.14.1、v1.3.0-rc.1；不接受空值、dev 或 latest。
新增版本检查要求目标 Tag 包含本次修改，旧 Tag 不具备完整的版本注入和校验能力。

## Windows 本地验证

```powershell
go run . --version
# dev

go build -ldflags "-X project/pkg/global.SYSTEM_VERSION=v1.3.0-rc.1" -o thingspanel.exe .
.\thingspanel.exe --version
# v1.3.0-rc.1
```

--version 在加载配置、连接数据库和 Redis 之前退出。

## Docker 本地构建

```powershell
docker build --build-arg VERSION=v1.3.0-rc.1 -t thingspanel-local:v1.3.0-rc.1 .
docker run --rm thingspanel-local:v1.3.0-rc.1 --version
```

不传 VERSION 时默认 dev。部署测试环境或生产环境不会改变包内版本；验收后建议部署同一个包或同一镜像摘要。
