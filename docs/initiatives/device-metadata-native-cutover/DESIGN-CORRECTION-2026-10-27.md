# 2026-10-27 设备模板设计纠偏（当前优先约束）

用户明确：**物模型需要版本功能；设备模板不需要版本表、草稿存储或发布版本功能。** 本决定覆盖此前工程候选中的相反设计。不是等待用户再次确认的选项。

## 查到的问题

1. `DECISIONS.md` D-DATA-004原本位于“工程取舍”，写了模板不可变发布版本、设备显式切版；这不是本次用户需要的功能，却被后续任务书当作必要前提。根代理沿用了该错误前提，应负责纠正。
2. 候选 `0023_access_template_revisions.up.sql` 引入 `device_access_template_revisions`；单一模板实体另有 `draft` JSON字段。`0026_device_access_bindings.up.sql` 又让设备绑定 `template_revision_id`。版本、草稿、切版由此扩散到API、CLI、UI和用例。
3. 1.3现有 `internal/model/device_configs.gen.go` 的 `NativeThingModelID/SnapshotID/Revision` 是**所选物模型**的版本引用。`internal/service/device_config.go` 在保存时验证该已发布物模型；`NativeBindingRevision`只是防止并发覆盖绑定的计数，不是模板历史版本表。前端config-detail也展示“已绑定”的物模型版本。它们不构成再建一套模板版本的理由。
4. “完整读取投影”指查询已有数据并整理成接口返回对象，当前没有另建投影表。对用户统一改称“模板列表/详情直接读库”。但候选返回draft、latestPublishedRevision及通过模板revision聚合设备，是被错误设计污染的读取，旧测试通过不证明设计符合需求。

## 修正后的边界

|对象|保留|删除或停止|
|---|---|---|
|物模型|现有草稿、发布版本、固定快照引用与模型资源；复用1.3已有核心|不重写物模型core，不把模型版本当模板版本|
|设备模板|普通列表/详情/创建/直接保存/删除、图片、Topic、脚本、扩展字段、注册配置及既有复制/导入导出功能；引用所选物模型版本|模板草稿语义/草稿存储、模板版本表、发布流程、历史版本查询、模板版本号选择/回滚|
|设备绑定|引用模板本身；沿用1.3已正常工作的模型绑定规则；实际必要校验和防覆盖保存|templateRevisionId绑定、仅因模板版本设计新增的独立切版预览/previewToken/发布后采用流程|
|普通接口底线|租户隔离、授权、输入校验、必要事务和防止并发覆盖、文件大小/MIME、已有功能的错误反馈|不因这些底线再制造新的业务页面、审批、草稿或发布功能|

模板只保留一份当前配置；`draft`不能只改名字后暗中保留“未发布/已发布”双状态。关联的物模型版本仍须明确。接口和表结构需要同步收简；已应用的候选测试migration保留原checksum，后续按确认的单份配置模型追加修正迁移，不能直接改坏已有迁移或误删物模型数据。候选未部署到生产。

## 补充纠偏：沿用1.3模板共用模型选择与普通成员移除

再次沿实际源码确认：设备模板菜单对应device_configs；1.3的native_thing_model_*绑定保存在该模板记录，devices只保存device_config_id。更新模板绑定后设备详情读当前device_config，消费者按其model/revision/snapshot读取。因此，模板选择发布版本7时关联设备用7；物模型仅发布8不会改变模板；模板明确保存选择8后，关联设备共同使用8。此前候选把相同模型指针复制到每台设备、使旧设备停7而新设备用8，是错误模板切版设计的残留，不能保留为新增功能。

追加0029（不改已应用0028checksum）：复用模板既有thing_model_id/thing_model_snapshot_id保存当前选中模型版本，配置保存时按tenant/model/精确revision解析并受现有复合外键保护；移除device_access_bindings的重复模型字段，设备读取经template_id关联模板选择。不复制或改动物模型版本内容，不引入模板版本表。尚待本轮实际回归通过，不能引用旧pin测试证明正确。
