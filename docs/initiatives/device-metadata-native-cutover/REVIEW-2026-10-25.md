## 1. 本轮结论

三个菜单应在同一版原生合同与数据边界下完整规划、并行实施、整版验收。当前指定checkout仍存在旧Community API调用、Encore旧投影/代理和CLI参数不一致，不能宣布三菜单原生切换完成。已有独立物模型候选的核心、固定快照、资源摘要、幂等和事务能力有真实源码与测试源，应选择性复用；本轮增补的是原生接线、边界与验收任务，不另建物模型核心或同义模板模块。

目标是：菜单/CLI业务用例 → 唯一正式Encore API → 唯一owner及新数据定义。未来MCP使用同一API与授权；内部服务合同按audience限制访问，不为CLI/MCP提供旁路。旧代码/旧库只作为行为与一次性迁移来源，目标没有旧API兼容、双读双写、旧表运行回退或旧元数据投影。

本轮发现目标目录已有一套规划，先读懂、保留稳定任务/功能ID，再修正事实和补齐缺口。规划规模及机器检查以最终VALIDATION文件和同源JSON为准；任务数、接口数、测试规格数、旧路由数均不是迁移完成率。
