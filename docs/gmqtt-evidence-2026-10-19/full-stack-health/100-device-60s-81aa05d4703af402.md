# Native broker full-stack health run

Run ID: `81aa05d4703af402` (2026-10-20 local, Asia/Shanghai). This is a single-stack health check, not a paired benchmark, performance certification, latency SLO, or production acceptance.

The isolated fixture used 100 distinct logical devices in one QA tenant, 100 clean MQTT sessions, QoS 1, and an open-loop target of 100 messages/s for 60 seconds. Payload sizes followed a fixed 90% 512-byte / 9% 4-KiB / 1% 64-KiB distribution. It sent 6,000 planned messages through the real Mosquitto 2.1.2 plugin, Owner HTTP, MQTT Adapter, Telemetry Uplink, storage batch writer, and isolated PostgreSQL schema. The fixture used a separately started ephemeral Redis process. It did not connect to the existing GMQTT, public backend, production Redis, or device fleet.

The event ledger records the planned device ID separately from every observed device ID. It retains all observed deliveries and ingestion/receipt IDs per planned `qa_id`; run-window telemetry receipts, `qa_id` SQL points, and effects are counted rather than collapsed into a set. All wrong-device, duplicate, and extra-row counters were zero. SQL and acceptance stage timestamps are collected after the send drain, so they are not latency samples. Generator lag is recorded, but no stage P99 is reported. Automation intents were observed; external side-effect execution was not observed.
