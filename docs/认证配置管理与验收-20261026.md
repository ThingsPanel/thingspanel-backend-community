# 认证配置管理与本地验收

日期：2026-10-26（Asia/Shanghai）。本文补充 v5 运行手册，记录本轮实现和本地验证；没有部署线上。本地 HTTPS 测试地址为 `https://localhost:5443`，使用开发证书，不是正式小程序的合法域名部署。

## 用户如何使用

平台超管进入“系统管理 → 系统设置 → 登录与认证”。可直接访问 `/management/setting?tab=authentication`。

1. 添加登录方式，选择微信小程序、企业 OIDC 或网站微信扫码。
2. 填写名称、来源凭据与允许使用的租户；租户按名称选择。密码登录始终保留。
3. 输入当前超管密码，保存草稿。保存不改变正在运行的配置，也不自动显示登录按钮。
4. 校验配置，完成当前版本的真实身份测试。
5. 输入密码启用这个版本。需要关闭时使用“停用”，不是删除账号或设备。

所有写操作由服务端验证普通人员会话、SYS_ADMIN 角色、非代登录状态及新鲜密码。租户管理员和普通用户不能管理平台提供方。

微信小程序测试使用新的 `wx.login` code，由服务器直接向微信换码；不创建用户、不绑定账号、不签发测试用户的平台会话。Web 来源测试使用带浏览器关联、state、PKCE/nonce（仅适用 OIDC）的真实授权流程，成功后返回本设置页，只记录所测试的草稿版本。来源仍须另行启用。

只启用小程序来源时，Web 和原生 App 不显示这个登录按钮。企业 OIDC 和网站微信仅作为已实现的 Web 来源；本期未新增原生 App 微信/OIDC 浏览器登录。

## 已实现的配置规则

- `sql/auth/003_provider_settings.sql` 由社区现有 auth 迁移账本管理，没有第二个账号数据库。
- 数据库分别保存草稿、生效快照、配置版本、测试版本、启用状态和世代号；编辑草稿保留旧生效快照。
- 未通过当前版本测试时，启用被拒绝；修改后需要重新校验和测试。
- 停用/重新启用递增世代号，旧授权事务不能因为重新启用而恢复有效。
- 公开接口从生效配置生成，敏感凭据不返回浏览器。后端按生效版本复用提供方客户端/JWKS 缓存，HTTP 连接有超时与空闲期限。
- 密钥采用 AES-256-GCM 加密，绑定提供方 ID；变更来源身份或令牌地址时不能隐式复用旧密钥。
- 提供方草稿或提供方存储错误不进入基础密码登录路径。基础账号库、签名密钥、会话库的真实故障仍拒绝认证。
- 文件配置中的来源必须显式 `enabled: true`；坏来源隔离并生成脱敏诊断，不阻断整个原生认证服务。
- 配置管理记录草稿保存、身份测试、启用与停用审计，不记录密码、Secret、code 或上游 token。
- 关闭第三方方式时，原登录页不显示空入口或“认证服务暂不可用”黄色警告。列表真实故障保留诊断，不把它伪装成管理员主动关闭。
- Web“记住我”改为“记住账号”，清除历史可还原密码值；不再保存 Base64 密码，也不接受 URL 账号密码自动提交。

## 部署配置

基础原生认证仍沿用 `TP_AUTH_MODE=native`、`TP_AUTH_CONFIG_FILE` 与 v5 的无 trace 自托管配置、HTTPS origin、原 DB/Redis、唯一会话所有者和受控网关。

后台可写配置新增环境变量：

```text
TP_AUTH_PROVIDER_KEY_FILE=/run/secrets/auth-provider-encryption-key
```

此文件保存独立生成的 32 字节随机密钥的标准 Base64 文本，服务只读。不要复用 JWT 签名密钥，不放入 Git、镜像或前端环境变量。备份提供方配置时必须同时受控备份该加密密钥；本轮没有实现主密钥轮换工具。

未提供该文件时，为文件管理模式，后台只读；文件错误时给出脱敏诊断并关闭可选来源。配置后台模式不会继续使用文件中的活动来源，需显式将需要的来源保存为草稿、验证、启用，避免双配置所有者。

OIDC 出站连接默认拒绝私有/环回/链路本地/共享地址，解析后直接连接已校验 IP，并拒绝 HTTP 重定向。确有私网企业 IdP 时，由部署者在 `TP_AUTH_OIDC_ALLOWED_ORIGINS` 配置精确 HTTPS origin JSON 数组；不是租户可修改的任意内网访问开关。TLS 证书校验保持开启。

生产网关原有 `deploy/auth/nginx-auth.locations.example.conf` 的 `/api/v1/auth/` 路由已经覆盖新接口。开发环境可显式设置 `VITE_AUTH_DEV_PROXY_TARGET`，将认证兼容路径交给唯一 Encore 所有者；不得只切换前端而保留第二个 Gin 会话写入者。

本地完成了强 JWT 密钥与 Gin/Encore 同步切换，使用既有用户库与 Redis，保留旧容器和数据库备份。旧本地会话需要重新登录。由于已有通知路由，业务后端必须保留原 source bridge 启用配置才能通过启动保护；本轮未修复历史 source/projection 凭据过期或重做告警投递验收。

## 新增接口

| 接口 | 权限与行为 |
| --- | --- |
| GET `/api/v1/auth/login-options?channel=web\|mp-weixin\|app` | 公开最小登录选项；未启用返回稳定空来源，不返回秘密 |
| GET `/api/v1/auth/external/providers` | 旧客户端兼容，沿用相同的生效来源 |
| GET `/api/v1/auth/admin/providers` | 超管读取脱敏配置、租户选项、测试/生效版本与部署诊断 |
| POST `/api/v1/auth/admin/providers` | 超管 + 当前密码；operation 为 save/validate/test/enable/disable，带 expectedRevision |

停用阻止新登录、绑定及未完成的来源事务；已经签发的平台会话仍按既有有效期处理。安全事件需要按用户撤销会话，不能将“停用来源”解释为已经提供全提供方精准会话清理。
