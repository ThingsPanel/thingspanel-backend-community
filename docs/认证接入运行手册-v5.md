## 不需要先部署 Casdoor

- 账号密码：使用现有 users、bcrypt 密码和 Redis，会话由社区仓库唯一 Encore 应用的 authn 负责。
- 微信小程序：客户端 wx.login 获取新 code，服务端直连微信 code2Session。无需 Casdoor。原生 App 微信登录不在本次范围。
- 企业登录：标准 OIDC Authorization Code + PKCE S256 + state + nonce。可直接接企业 IdP；以后若使用 Casdoor/Keycloak，也作为 OIDC 来源接入。
- 上述入口共享原 UserID、显式绑定、账号状态、租户、角色、认证版本和通知资格校验，不复制账号数据库。
- 不凭邮箱、手机号、昵称或 UnionID 自动合并账号。OpenID 以 AppID 分域；外部身份未绑定只返回 binding_required。

## 服务端配置

复制 deploy/auth/auth.config.example.json 到仓库外私密文件，限制只有运行用户可读。不要将密钥、完整配置或 token 写进 issue、日志或 Git。

必须配置现有社区 PostgreSQL 与 Redis 地址、现有 JWT key（至少 32 字节）、会话秒数、密码锁定策略及同源 HTTPS publicOrigin。rsaPrivateKeyFile 仅在既有 frontend_res 加密模式启用时填写原 RSA 私钥路径。此模式仍需单独核验 App 端兼容性，当前 App 没有新增 RSA 客户端实现，不能据此宣称该模式的手机登录已经通过。

providers 默认为 []，因此不需要外部服务即可部署密码认证。启用前逐项验收，只添加通过的来源。

微信来源示例（仅字段说明，密钥在私密文件填入）：

```json
{
  "id": "wechat-mini",
  "label": "微信登录",
  "kind": "wechat-mini",
  "appId": "你的小程序 AppID",
  "appSecret": "在私密配置中填写",
  "tenantIds": ["允许使用的现有租户 ID"],
  "reviewId": "本次来源验收记录编号"
}
```

微信调用地址固定为 https://api.weixin.qq.com/sns/jscode2session，不能通过配置把 AppSecret 发往其他地址。session_key 不返回、不入库；UnionID 不用于绑定。小程序后台必须配置平台 HTTPS request 合法域名。AppID 要与 App manifest 一致，AppSecret 不能打进客户端包。未提供密钥、域名及真机前不展示正式入口。

OIDC 来源示例：

```json
{
  "id": "enterprise",
  "label": "企业账号登录",
  "kind": "oidc",
  "issuer": "https://idp.example.com/精确的issuer",
  "clientId": "专用web-client",
  "clientSecret": "在私密配置中填写",
  "authorizeUrl": "https://idp.example.com/官方授权端点",
  "tokenUrl": "https://idp.example.com/官方令牌端点",
  "jwksUrl": "https://idp.example.com/官方JWKS端点",
  "redirectUrl": "https://panel.example.com/api/v1/auth/external/callback",
  "tenantIds": ["允许使用的现有租户 ID"],
  "reviewId": "本次来源验收记录编号"
}
```

端点取自实际来源元数据，不能照抄示例域名。当前支持 RS256、保密客户端及标准 id_token；只提供 OAuth access_token 的厂商接口不能当作 OIDC 使用。必须验证 issuer/aud/exp/sub/nonce、PKCE、换码失败、同邮箱等上游合并行为、账号删除重建。reviewId 只是部署审计标识，不会自动证明上游安全配置。平台超管默认不能通过这些外部入口登录。

## 构建、切换与发布门槛

1. 备份社区 DB/配置，记录镜像和 schema 校验和。先在隔离副本演练。
2. 社区后端启动执行 ApplyAppPushSchema 后执行 ApplyAuthSchema；sql/auth/001_identity.sql 与 002_self_unlink.sql 使用独立组件账本，启动校验 checksum 和关键约束。不要修改 sys_version 或重放历史 26/27.sql，不要让 Encore 再管理同一账号 schema。
3. 从社区 encore-api 根构建统一应用：`encore build docker YOUR_REGISTRY/thingspanel:VERSION --skip-config`。已用 Encore CLI 1.58.8 构建完整应用。本地 authn-only 启动只是隔离验证，不是新增生产认证服务。
4. 生产为自托管 Linux 镜像，关闭请求/响应及外部 HTTP trace。配置 ENCORE_INFRA_CONFIG_PATH 为只读绝对路径，TP_AUTH_INFRA_CONFIG_PATH 同值，TP_AUTH_INFRA_SHA256 为该文件实际 SHA256；TP_AUTH_PRIVACY_READY=1、TP_AUTH_MODE=native、TP_AUTH_CONFIG_FILE 指向私密配置。不允许 ENCORE_RUNTIME_CONFIG、ENCORE_TRACE_*、OTEL_* 或 infra observability/trace 配置。普通 encore run 的开发 trace 环境会拒绝凭据服务，不能绕过保护开关。
5. infra 必须保留整个应用的数据库、服务及通知配置，不能把隔离 authn 的 fixture 配置复制生产。log_config 是 Encore 接受的字符串格式，使用该版本生成的 infra 模板。密码/微信密钥/URL query 不得进网关、代理或 APM 日志。
6. 部署匹配的 Web 和 App。在同源 HTTPS 网关合入 deploy/auth/nginx-auth.locations.example.conf；/auth-callback 返回前端 SPA。路由及 TP_AUTH_OWNER=encore 同批切换，旧 Gin 登录/续期/代登录/注册/初始化 writer 返回 503。Gin/Encore 内部端口不对公网开放；保留网关按实际客户端 IP 限流。core 不信任任意 X-Forwarded-For。
7. 实际使用旧账号核对 user ID、租户资产和权限、单登/共享、退出/冻结/版本撤销、App CID 资格。密码重置/邮件验证码等未迁移业务路径仍在 Gin，敏感账号接口不再记录请求/响应正文。
8. 每个外部来源独立开启。没有真实企业 IdP、小程序凭据和手机验收时 providers 保持为空，不要求先安装 Casdoor。

## 绑定停用及恢复

所有请求使用人员 Bearer 会话，不得用插件/API Key/代登录会话。

- GET /api/v1/auth/bindings：当前账号；管理员可带 user_id 查询授权范围内用户。
- POST /api/v1/auth/bindings/unlink：当前用户验证密码后主动解绑自身身份；保留归属、递增认证版本并停用推送设备。所有旧会话失效；可用密码重新登录并通过全新第三方证明重新绑定。不能解除管理员停用。
- POST /api/v1/auth/bindings/disable：JSON 包含 bindingId、password（加密模式还带 salt）。平台管理员，或同租户管理员对普通用户操作。需要重新验密。原绑定保留；认证版本递增、推送设备失活，旧会话在后续请求失效。
- POST /api/v1/auth/bindings/allow-rebind：同样的管理员会话、权限和验密。只批准原持有人在 10 分钟内重新绑定；不会直接恢复登录，不改变归属。
- 原持有人用密码重新登录，再走全新的 OIDC 绑定流程或小程序 bind（新 code）。成功后消耗批准；过期则重新审批。再次停用会取消批准。

后台接口已具备，尚未增加专门的可视化管理员绑定管理页。已被外部推送服务接收的消息不承诺撤回；已建立的长连接也不承诺即时关闭。
