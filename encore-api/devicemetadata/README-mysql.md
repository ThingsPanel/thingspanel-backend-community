Run the tests:

```bash
scripts/dev-databases.sh up
# build the oracle: psql ... -d device_metadata < each devicemetadata/migrations/*.up.sql in numeric order
export TP_DM_PG_DSN='postgres://postgres:pw@127.0.0.1:56001/device_metadata?sslmode=disable'
export TP_DM_MYSQL_DSN='root:pw@tcp(127.0.0.1:56002)/device_metadata?parseTime=true&clientFoundRows=true&loc=UTC&multiStatements=true'
(cd encore-api && go test ./devicemetadata/mysqlschema/ ./pkg/dbx/)
```

The MySQL contract test requires `TP_DM_MYSQL_DSN` to point to an isolated database with permission to create schema objects. It applies the metadata schema before running and leaves that schema in place.

## Measured: how much SQL the translator already accepts

`go test -v -run Translatability ./devicemetadata/mysqlschema/` scans the service's non-test Go files: **335 of 371 SQL statements (90%)
translate as they are**. The 36 that do not are listed, with file and statement text, in `MYSQL-REFUSED-STATEMENTS.txt`
(regenerate with `TP_DM_REFUSED_FILE=<path> go test -run Translatability ./devicemetadata/mysqlschema/`). By cause: 24 `RETURNING`
(15 in `store.go`), 8 casts the translator does not know (`$n::interval`, `jsonb_build_array`, `jsonb_agg`), 3 `ARRAY`/`ANY` in
recursive group queries, 1 `ILIKE` inside a larger expression. Translating is not the same as correct: each converted file still
needs a PG-versus-MySQL scenario test (copy `automation/store/mysql_runs_contract_test.go`).

## Not done

1. **The facade is wired, but MySQL SQL coverage is partial.** The `dbx` type conversion and `TP_DEVICE_METADATA_DB_DRIVER=mysql`
   selector are in place. A tested vertical slice covers thing-model create, point read, and list; the remaining stores still contain
   translator-rejected forms (`RETURNING`, `ILIKE`, `COUNT(*) OVER()`, JSON functions, `FOR UPDATE SKIP LOCKED`, `ON CONFLICT ... WHERE`).
   Add MySQL branches and differential contracts by domain, using `automation/store/translatability_report_test.go` as a model.
   A real Encore process has not yet been shown to start with no reachable PostgreSQL; `sqldb.NewDatabase` remains declared at package scope.
   MySQL update and device-number collision/exclusion branches are now in the contract test, but have not been run against MySQL; that
   test was skipped because a temporary database container could not start when Docker reported `No space left on device`.
2. **Row level security is absent on MySQL.** PostgreSQL's only policy is on `audit_log`. Tenant-scoped SQL transactions no longer call
   PostgreSQL `set_config` on MySQL; every statement must filter by `tenant_id` itself. The new contract covers only thing-model
   create/read/list and one transaction path. The separate `beginTenantGroupTx` callers still use raw `database/sql` transactions,
   and all stores need cross-tenant read/write/list coverage before enabling the profile broadly.
3. **Three guards are not ported** (they are the complex ones): `validate_gateway_membership_tree` (cycle and depth limits, advisory lock),
   `enforce_gateway_memberships_after_device_state_change` (deferred constraint trigger: re-check at commit), and
   `resolve_current_template_model_selection` (fills `thing_model_id`/`thing_model_snapshot_id` from `configuration`).
   Port them as triggers with `tp_advisory_locks` row locks, or as application checks in the same transaction, and prove them with
   PG-versus-MySQL scenarios (cycle, depth 33, self reference, concurrent edges).
4. **11 CHECK constraints are not converted** because they call PostgreSQL functions or use `btrim(x, chars)`: the device identity validators
   (`device_identity_*_valid`, device number / subdevice address whitespace rules), `device_access_binding_parameters_valid`,
   `metadata_operation_problem_shape`, `metadata_operation_result_shape`. The generator prints them. Validate in application code or in triggers.
5. Seed data from migration `0002_seed_meta_item_keys` is exported in `mysqlschema/003_seed.sql` and compared with PostgreSQL by
   `TestSchemaMatchesPostgres`. It uses fixed IDs and the unique `(tenant_id, key)` index to apply repeatedly.
