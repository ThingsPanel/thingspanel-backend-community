## Not done

1. **The Go code still calls `encore.dev/storage/sqldb` directly** (about 330 call sites in 81 files: `db.Query/QueryRow/Exec/Begin`,
   `*sqldb.Tx`, `*sqldb.Rows`, `*sqldb.Row`, helper interfaces such as `QueryRow(...) *sqldb.Row`). Convert by type rename to
   `dbx.DB/Tx/Rows/Row`, make `db` a `dbx.DB` chosen at start-up (Encore for PostgreSQL, `dbx.SQL(sqldialect.OpenMySQL(dsn), "mysql")`
   for MySQL), and replace `isUniqueViolation` with `dbx.IsUniqueViolation`. Statements the translator refuses
   (`RETURNING`, `ILIKE`, `COUNT(*) OVER()`, `jsonb` functions, `FOR UPDATE SKIP LOCKED` forms, `ON CONFLICT ... WHERE`) need a MySQL branch
   as in `automation/store`; `translatability_report_test.go` there shows how to measure.
   Whether Encore starts without a reachable PostgreSQL (`sqldb.NewDatabase` is declared at package level) must be tried with the
   real `encore` build before relying on it.
2. **Row level security is gone on MySQL.** PostgreSQL's only policy is on `audit_log`, but `beginTenantScopedSQLTx` sets
   `app.current_tenant_id` for every tenant-scoped transaction; on MySQL every statement must filter by `tenant_id` itself. Add a
   cross-tenant test per store (see `cross_tenant_test.go`) before turning the MySQL profile on.
3. **Three guards are not ported** (they are the complex ones): `validate_gateway_membership_tree` (cycle and depth limits, advisory lock),
   `enforce_gateway_memberships_after_device_state_change` (deferred constraint trigger: re-check at commit), and
   `resolve_current_template_model_selection` (fills `thing_model_id`/`thing_model_snapshot_id` from `configuration`).
   Port them as triggers with `tp_advisory_locks` row locks, or as application checks in the same transaction, and prove them with
   PG-versus-MySQL scenarios (cycle, depth 33, self reference, concurrent edges).
4. **11 CHECK constraints are not converted** because they call PostgreSQL functions or use `btrim(x, chars)`: the device identity validators
   (`device_identity_*_valid`, device number / subdevice address whitespace rules), `device_access_binding_parameters_valid`,
   `metadata_operation_problem_shape`, `metadata_operation_result_shape`. The generator prints them. Validate in application code or in triggers.
5. Seed data of migration `0002_seed_meta_item_keys` is not exported yet (same approach as `scripts/pg2mysql_seed.py`).
